PARMCO: Real-Time Mobile Motor Control Interface

PARMCO is the human-machine interface (HMI) for the RP4 motor system. Developed natively for Android, it provides seamless, responsive control and instantaneous feedback, crucial for closed-loop stability.

Intuitive UI (Jetpack Compose)

Features a custom **Rotary Speed Dial** for setting target RPM, direction toggles, and a prominent real-time RPM gauge for immediate visual confirmation.

State Management

Uses Kotlin's **StateFlow** architecture to manage complex connection states (Connecting, Connected, Disconnected) and to ensure UI updates are synchronized with embedded data streams.

Command Protocol

Sends plain-text commands over Bluetooth SPP, such as `TARGET:4500` or `FORWARD`, minimizing overhead and maximizing processing speed on the RP4.

Error & Feedback Handling

Displays critical status flags, including connection strength, controller state (Open/Closed Loop), and any error codes received from the RP4 firmware.

Bifurcated Software Architecture: Mobile Client and Embedded Server

Client Side: Android App (Kotlin)

The mobile application handles user input, visual feedback, and reliable Bluetooth data transmission. High-priority commands are sent immediately, while state data is polled at a 50ms interval.

  • Bluetooth Manager: Dedicated service using Kotlin Coroutines to handle the low-level socket connection and maintain a persistent, high-throughput RFCOMM stream.
  • MVVM Pattern: Enforces separation of concerns, ensuring UI logic (Views) remains clean and decoupled from data handling (ViewModels) and the communication layer (Model).
  • Latency Mitigation: The App timestamps outgoing commands and compares them to the RP4's system clock (sent with every status message) to calculate and display network latency.

Server Side: Embedded System (Bare-Metal C)

The Raspberry Pi runs a highly efficient C program, using the pigpio library for fast, non-blocking GPIO access and hardware-based PWM generation to achieve microsecond-level control resolution.

Control Loop Frequency: 100 Hz (10 ms period)

All PID calculations and PWM adjustments occur at this fixed, high-frequency rate.

PID Implementation: Incremental PID (Position-based)

Calculates the necessary change in PWM duty cycle (u(k) - u(k-1)) to prevent integral windup and ensure smooth transitions.

Motor I/O: pigpio library

Used for reliable hardware PWM generation (GPIO18) and high-resolution pulse counting (GPIO22).

Embedded Control and Circuit Details Overview

The system integrates the low-voltage Raspberry Pi logic with a high-current 12V power stage, using robust components to ensure safety and power efficiency.

RP4: Control Core (3.3V Logic)

The Pi is powered by a dedicated 5V supply and its GPIO pins provide the low-power logic signals for the motor driver. All control signals are active-high at 3.3V.

Direction Pins: GPIO17, GPIO27

PWM Output: GPIO18 (Hardware PWM for stability)

Feedback Input: GPIO22 (ISR attached for pulse counting)

Operating System: Custom bare-metal OS or minimal Linux with real-time kernel modifications.

L293D & MOSFET: Power Isolation (12V)

The motor requires 12V and up to 1.5A peak current. The L293D H-Bridge is used to flip polarity, while an external MOSFET (IRF744N) handles the high-current PWM switching on the H-Bridge's enable pin.

V_MOTOR: 12V DC

V_LOGIC: 5V DC (L293D internal logic supply)

H-Bridge Role: Directional switching (IN1/IN2)

MOSFET Role: Power gating (Enable pin control via PWM)

IR Sensor: Speed Feedback (3 PPR)

An infrared reflective optical sensor is mounted to detect a patterned wheel on the motor shaft, providing **3 Pulses Per Revolution (PPR)**. This high-resolution input is critical for accurate speed calculation at low RPMs.

Sensor Output: Digital (High/Low)

Signal Conditioning: Pulses are cleaned via a Schmitt trigger (software or hardware) before feeding into GPIO22 to prevent false readings (chatter).

RPM Calculation: Time between successive pulses is measured via Interrupt Service Routines (ISRs) for high-precision velocity determination.

Detailed Power and Logic Interfacing (Circuit Analysis)

Reference: RP4 Motor Control System - Complete Wiring Diagram.

Low-Side Logic Path (RP4 to Driver)

The low-side involves the signals that control the operation of the high-side power stage. The Pi's GPIO pins operate at 3.3V and must only connect to the logic inputs of the L293D.

  • **Direction (GPIO17/27 to IN1/IN2):** Direct connection. The L293D accepts 3.3V as a valid logic HIGH.
  • **PWM (GPIO18 to MOSFET Gate):** The 3.3V PWM signal drives the gate of the MOSFET (Q1). The MOSFET acts as an electronic switch for the VCC2 (12V) path to the L293D's Enable pin. This is a crucial design choice to prevent the Pi's GPIO from sourcing the required current for the L293D's internal enable logic.
  • **Logic Isolation:** The H-Bridge power supply (VCC1) is set to 5V, separate from the 12V motor supply (VCC2), ensuring the Pi's 5V rail is not contaminated by motor spikes.

High-Side Power Path (Motor Driver to Motor)

This path carries the high current and high voltage required to run the DC motor. Protection and filtering are paramount here.

  • **Motor Supply (VCC2):** 12V DC, connected directly to the L293D's power pins (Pin 8).
  • **Inductive Spike Protection:** The L293D has internal clamping diodes, but external flyback diodes (not explicitly shown but assumed necessary for large motors) are recommended across the motor terminals to sink high-voltage spikes generated when the PWM duty cycle rapidly drops.
  • **Ground Planes:** The motor ground (GND2) is connected to the Pi's common ground (GND1), but filtering capacitors are strategically placed to minimize noise injection from the motor to the sensitive Pi logic.
  • **Current Monitoring:** The design allows for future integration of a shunt resistor or Hall effect sensor on the motor ground return path for real-time current limiting.

PI Controller Deep Dive and Control Mode Analysis

The PI Control Loop Algorithm

The core of the closed-loop system is the Proportional-Integral (PI) controller, which regulates the actual RPM ($\text{PV}$) to the target RPM ($\text{SP}$) by adjusting the PWM duty cycle ($\text{u}$).

Discrete PI Equation:

Error: $e(k) = \text{SP} - \text{PV}(k)$

Proportional Term: $P(k) = K_p \cdot e(k)$

Integral Term: $I(k) = I(k-1) + K_i \cdot e(k) \cdot T_s$

Controller Output: $u(k) = P(k) + I(k)$

Where $T_s$ is the sampling period (10 ms).

Tuning Parameters (Ziegler-Nichols Method):
  • **$K_p = 0.015$**: Provides fast reaction to sudden load changes.
  • **$K_i = 0.001$**: Eliminates steady-state error (the difference between SP and PV) over time.
  • **Derivative Term ($K_d=0$):** Omitted as PI control is sufficient for this simple DC motor system, avoiding high-frequency noise amplification.

Simulated Performance Metrics

The tuned PI controller yields excellent dynamic response characteristics for the 4500 RPM target step command.

Rise Time (0 to 90%): 1.8 seconds
Overshoot: ~0.2% (Max RPM 4510)
Settling Time (±30 RPM deadband): 3.2 seconds
Robustness Test (Load Disturbance):

A simulated step change in motor load at $\text{t}=6.0$ seconds resulted in a momentary drop of 250 RPM, which the controller corrected back to the target speed within 1.0 second, demonstrating excellent load rejection.
