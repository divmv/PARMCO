Project Architecture and Implementation

Software Stack (Android)

The application is natively developed in Kotlin, utilizing the latest Android frameworks for a high-performance, responsive interface.

  • Jetpack Compose: Used for building the entire UI, including custom, animated components like the Rotary Speed Dial and real-time RPM display.
  • Kotlin Coroutines: Manages asynchronous operations like Bluetooth communication without blocking the main thread.

Bluetooth Communication Layer

Communication with the physical motor controller (a designated Raspberry Pi) is handled via the classic Bluetooth Serial Port Profile (SPP).

Protocol: Bluetooth RFCOMM (SPP)

Hardware Target: RP4 MAC Address (`2C:CF:67:53:61:32`)

Embedded Control and Circuit Details Overview

The core control logic runs directly on the **Raspberry Pi 4**. The system is optimized for speed and reliability using a specialized bare-metal C program that handles everything from input/output to closed-loop speed regulation.

RP4: The Master Controller

The Raspberry Pi serves as the brain, executing the C-based control firmware and managing Bluetooth communication with the mobile app. Its GPIO pins are meticulously configured for specific motor I/O tasks.

Direction Control (A): GPIO17 (IN1)
Direction Control (B): GPIO27 (IN2)
Speed Modulation: GPIO18 (PWM)
Feedback Input: GPIO22 (RPM)

Power Stage: L293D & MOSFET

This section handles the high-current 12V motor supply, isolating it from the low-voltage 3.3V Pi logic. Direction is set by the **L293D H-Bridge** (a dual H-bridge IC). Speed is controlled by the **IRF744N MOSFET** switching the H-Bridge's enable pin.

L293D Specs: Dual channel, 600mA output capacity, accepts 3.3V logic.

PWM Integration: A PWM signal drives the MOSFET gate through a 1kΩ resistor.

Safety: Built-in flyback diodes protect components from motor inductive spikes.

Speed Feedback and PID Loop

RPM Sensing

An **IR reflective sensor** detects rotation via markings on the motor shaft, generating **3 pulses per rotation**. This digital stream is timed by the Pi to calculate instantaneous RPM.

PI Controller Tuning

The controller uses a **PI (Proportional-Integral) loop** for smooth, error-free speed locking. The parameters are tuned to minimize overshoot while ensuring rapid convergence to the target RPM.

Kp (Proportional Gain): 0.015 Ki (Integral Gain): 0.001 Target Deadband: ±30 RPM

The Tripartite System: Power, Direction, and Feedback

The complete circuit illustrates a robust, three-stage architecture. The **Raspberry Pi** acts as the low-voltage brain, sending commands to the high-voltage motor stage via the H-Bridge and MOSFET, while simultaneously receiving essential speed data from the IR sensor to close the control loop.

1. Commanded Rotation (Direction)

Motor direction is managed by the **L293D H-Bridge** chip. The Pi uses two dedicated control pins, **GPIO17 (IN1)** and **GPIO27 (IN2)**, to flip the voltage polarity applied across the DC motor. This ensures an immediate switch between Forward (FWD) and Reverse (REV) movement based on the mobile app's input.

2. Power Regulation (PWM)

Speed is controlled using **Pulse Width Modulation (PWM)** from the Pi (**GPIO18**). Critically, this signal passes through the **Q1 MOSFET**, which acts as an inverting switch for the L293D's **Enable (EN1)** pin. This configuration means the MOSFET toggles the 12V supply, allowing the Pi to modulate the motor's power while drawing minimal current from its own GPIO pins.

3. Real-Time Feedback (RPM)

The system achieves closed-loop control through an **IR reflective sensor**, which monitors the motor shaft. Each rotation generates three digital pulses that feed directly into **GPIO22**. The Pi’s C program analyzes the frequency of these pulses to calculate the motor's current **RPM**, providing the essential input for the PID controller.

Dual Control Modes and Command Structure

1.

Manual PWM Mode (Open Loop)

In Manual mode, the user directly commands the motor's raw power level by setting the **Duty Cycle** (0-100%). The controller executes this command without adjusting for load or actual speed.

Command Format:
"50" (Sets PWM to 50%)
"START" / "STOP"
2.

Automatic Target RPM Mode (Closed Loop)

In Automatic mode, the user sets a specific **Revolutions Per Minute (RPM)** target. The embedded system utilizes the PID controller to automatically adjust the PWM to maintain the target speed under varying loads.

Command Format:
"TARGET:4500" (Requests 4500 RPM)
"FORWARD" / "REVERSE"
